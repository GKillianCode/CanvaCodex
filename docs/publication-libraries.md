# Publication et bibliothèques partagées

## Accueil

La recherche accepte `playlist:`, `vidéo:`, `type:` et `statut:`. `état:`, `etat:` et `status:` sont aussi reconnus pour les statuts. Sans filtre de statut, tous les statuts sont visibles. `statut:all` inclut tous les statuts et `statut:none` les masque tous. Plusieurs statuts forment une sélection élargie ; les autres familles de filtres restent combinées entre elles. Les noms personnalisés et les identifiants sont acceptés, par exemple `statut:"Prêt à tourner"`.

Les suggestions fonctionnent pour les mots-clés puis leurs valeurs. Flèches haut/bas pour choisir, Entrée ou Tab pour insérer, Échap pour fermer. La recherche, le tri, les archives et la pagination restent mémorisés. L’ancien masque de statuts de « Affichage » n’est plus appliqué. Le tri reste disponible à côté de la recherche, et l’icône Archives conserve son action.

Playlists, Notes et Parcours sont accessibles dans l’en-tête de l’accueil.

## Musiques

Fichier → Bibliothèque de musiques ouvre une page complète sans masquer la navigation. La liste se recherche par titre/artiste et se trie par nom, artiste ou ordre d’ajout. Chaque fiche contient titre, artiste, lien et crédits/licence. La suppression demande confirmation.

Les fiches enregistrées sont en lecture seule. Le crayon dans la liste ou dans la fiche active la modification. Une nouvelle fiche est directement éditable ; Enregistrer la verrouille à nouveau. Les modifications sont enregistrées avant une navigation interne. En cas d’échec de lecture, aucune bibliothèque vide ne remplace les données existantes.

Dans Publication, choisir/cocher les musiques de la vidéo génère le bloc de crédits à copier. « Gérer la bibliothèque de musiques » ouvre la même page et permet de revenir ensuite à la publication. La bibliothèque est commune aux vidéos de cette application.

## Modèles de description

Fichier → Modèles de description ouvre deux listes : Modèles et Blocs réutilisables.

Un modèle contient un texte fixe de début, jusqu’à 20 parties interchangeables et un texte fixe de fin. Chaque partie possède un nom et éventuellement un bloc par défaut. Une playlist peut être renseignée pour proposer ce modèle en priorité. Un modèle sans playlist convient à toutes les vidéos.

Un bloc réutilisable contient un nom et du texte : présentation d’un outil, ressources, précisions sur une version de Java, liens, etc. Les fiches sont verrouillées après enregistrement, modifiables via leur crayon. Les parties du modèle se réordonnent avec leur poignée.

Dans Publication → Composer avec un modèle, choisir un modèle puis un bloc ou un texte propre à la vidéo pour chaque partie. « Ne pas inclure » permet d’omettre une partie. L’aperçu montre le résultat avant application. Appliquer remplace la description avec confirmation si elle n’est pas vide ; une action permet d’annuler ce remplacement. La composition devient du texte libre, sans modification automatique des descriptions déjà écrites lorsque la bibliothèque évolue. Les choix de composition sont sauvegardés dans la vidéo. Les anciens modèles par playlist restent accessibles depuis le compositeur.

Ces bibliothèques sont enregistrées dans les paramètres locaux partagés de l’application. Une sauvegarde de vidéo conserve sa description finale et ses choix, mais ne transporte pas l’intégralité de ces bibliothèques.

## Chapitres et flèches

La poignée à gauche d’un chapitre permet de le déplacer. Le trait montre le point d’insertion, au-dessus ou au-dessous d’une ligne. La dernière modification de liste reste annulable. Les horaires restent attachés aux chapitres ; les contrôles signalent les horaires à ajuster après un réordonnancement.

Dans Fichier → Paramètres des vidéos, « Afficher les flèches de réordonnancement » est un réglage d’interface appliqué immédiatement à toute l’application et conservé dans le navigateur. Il est désactivé par défaut. Il concerne les boutons de montée/descente des listes, pas les commandes de navigation ou de transformation.

## Supports sans titre

Depuis la fiche vidéo, le nom d’un nouveau support peut rester vide. L’application choisit le premier numéro libre pour le type concerné : Diaporama - 1, Incrustation - 1, Miniature - 1 ou Animation - 1. Un nom saisi reste prioritaire.
